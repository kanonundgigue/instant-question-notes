パレート最適化とは？

作成日: 2026-07-31

更新日: 2026-08-11

カテゴリ: statistics

元の質問

パレート最適化とは？

回答

パレート最適化は、コスト、精度、速度、安全性など複数の目的が競合する問題で、一つの総合点を最小化する代わりに、目的間の優れた妥協案をまとめて探す考え方です。ある解を改善するには少なくとも別の目的を悪化させる必要があるとき、その解をパレート最適解と呼びます。通常は一つではなく複数の解が残り、それぞれが異なるトレードオフを表します。[1]

最初に4つの用語を区別する

目的

良くしたい評価項目です。ここでは「費用」と「誤差」をどちらも小さくする問題を考えます。目的には最大化と最小化を混在させることもできますが、比較するときは各目的でどちらが良い方向かを明示します。

支配

解Xが解Yに対して、すべての目的で同等以上であり、少なくとも一つの目的で明確に優れているとき、「XはYを支配する」といいます。最小化問題なら、Xの値が全項目でY以下で、少なくとも一項目ではYより小さい状態です。[1]

パレート最適解

実行可能な他の解に支配されていない解です。「非支配解」または「効率的な解」と呼ばれることもあります。パレート最適解をすべて集めたものが、決定変数の空間におけるパレート集合です。[1]

パレートフロント

パレート最適解を、費用や誤差などの目的値の空間に写して並べた境界です。パレート集合が「どの設計を選んだか」を表すのに対し、パレートフロントは「その設計がどの成績を達成したか」を表します。[1]

5案の数値例で支配関係を見る

次の5案について、導入費用と予測誤差をどちらも小さくしたいとします。

設計案 費用 誤差
A 80万円 8%
B 100万円 5%
C 120万円 3%
D 110万円 6%
E 90万円 9%
  • DはBに支配される: Bの方が10万円安く、誤差も1ポイント小さいため、Dを選ぶ理由がありません。
  • EはAに支配される: Aの方が10万円安く、誤差も1ポイント小さいため、Eも候補から外せます。
  • A、B、Cは互いに支配しない: 誤差を小さくするほど費用が上がります。どれか一つを一方的に優れているとはいえません。

したがって、この候補集合におけるパレート最適解はA、B、Cです。ただし、これは列挙した5案の中での非支配解です。調べていない設計案や探索範囲の外に、A、B、Cを支配する解が存在しないことまでは保証しません。

Python演習: 気象予報モデルのPareto frontを探す

ある地点の翌日気温を予報する6種類のモデルを比較します。評価軸は、予報値と観測値のずれを表すRMSE（平均二乗誤差の平方根）と、1回の予報に必要な計算時間です。どちらも小さいほど良いものとします。次の数値は仕組みを学ぶための合成データであり、実在する気象予報モデルの性能ではありません。

モデル RMSE 計算時間
A: 高解像度1.4 K40分
B: 標準1.8 K18分
C: 軽量2.3 K7分
D: 旧版2.1 K22分
E: 実験版1.6 K32分
F: 簡易版2.5 K12分

「XがYを支配する」とは

これは、Yより悪い項目がXには一つもなく、少なくとも一項目ではXの方が良いという意味です。言い換えると、今回比べているRMSEと計算時間だけを見る限り、Yを残す理由がなくなる状態です。

BとDを比べると、BのRMSEは1.8 KでDの2.1 Kより小さく、Bの計算時間は18分でDの22分より短くなっています。Bは精度と速さの両方でDに勝つので、BがDを支配します。

B → D を比較
RMSE:     1.8 <= 2.1  → Bの方が良い
計算時間: 18  <= 22   → Bの方が良い
結論: BはDを支配する

一方、AとBでは、Aの方が正確ですが、Bの方が速く計算できます。片方のモデルが両項目で勝っているわけではないため、AとBは互いを支配しません。

A → B を比較
RMSE:     1.4 <= 1.8  → Aの方が良い
計算時間: 40  <= 18   → False（Aの方が遅い）
結論: AはBを支配しない

問題

  1. 表を見て、他のモデルに支配されるモデルを予想してください。
  2. 比較モデルが判定対象モデルを支配するか調べる関数 dominates を完成させてください。
  3. どのモデルにも支配されないモデルを抽出し、Pareto frontを求めてください。

まず、次の雛形の ... を条件式に置き換えます。

def dominates(comparison_model, target_model):
    no_worse = ...
    strictly_better = ...
    return no_worse and strictly_better

ヒント

comparison_model は「勝てるか調べる側」、target_model は「支配されるか調べられる側」です。dominates(B, D) は「BがDを支配するか」と左から読みます。

no_worse は「比較モデルのRMSEと計算時間が、どちらも判定対象以下」、strictly_better は「少なくとも片方が判定対象より小さい」という条件です。同じ値のモデル同士を、誤って支配関係にしないために両方が必要です。

解答と実行結果を見る

解答では、候補ごとに「その候補を支配する別モデルが一つでもあるか」を any で調べます。

def dominates(comparison_model, target_model):
    no_worse = (
        comparison_model["rmse_k"] <= target_model["rmse_k"]
        and comparison_model["runtime_min"] <= target_model["runtime_min"]
    )
    strictly_better = (
        comparison_model["rmse_k"] < target_model["rmse_k"]
        or comparison_model["runtime_min"] < target_model["runtime_min"]
    )
    return no_worse and strictly_better


pareto_front = []
for candidate in models:
    is_dominated = any(
        dominates(other, candidate)
        for other in models
        if other is not candidate
    )
    if not is_dominated:
        pareto_front.append(candidate)

DはBに、FはCに支配されます。A、E、B、Cは、精度を上げるほど計算時間が長くなる関係にあるため、互いを支配しません。

Pareto frontに残る予報モデル
A: 高解像度: RMSE=1.4 K, 計算時間=40分
B: 標準: RMSE=1.8 K, 計算時間=18分
C: 軽量: RMSE=2.3 K, 計算時間=7分
E: 実験版: RMSE=1.6 K, 計算時間=32分

考察

Pareto frontに残ったからといって、Aが常に最善とは限りません。たとえば予報を10分以内に配信する必要があるならCだけが条件を満たします。実務では、Pareto frontを求めた後に配信期限、計算資源、許容できる誤差などを使って一案を選びます。

次の段階として、南極古気候の候補を蓄積量と複数プロキシで絞る演習では、必要条件を先に適用してからPareto frontを求めます。

実際のパレート最適化は何をするか

  1. 決定変数を決める: 設計寸法、材料、運転条件など、変更できる値を定義する。
  2. 目的を決める: 費用、誤差、所要時間など、比較したい指標と良い方向を定義する。
  3. 制約を決める: 予算上限、安全基準、物理法則など、必ず満たす条件を定義する。
  4. 候補を探索する: 厳密法、重み付き和、制約法、進化計算などを使って解を生成する。
  5. 非支配解を残す: 支配される候補を除き、パレートフロントを近似する。
  6. 最後に一案を選ぶ: 予算、許容誤差、頑健性など、最適化に入れていない判断基準も含めて意思決定する。

代表的な進化計算手法のNSGA-IIは、候補集団を非支配ランクで並べ、混雑距離を使って解の多様性を保ちながら、1回の探索で複数のパレート最適解へ近づく方法です。ただし、得られるのは有限回の計算による近似であり、真のパレートフロント全体が必ず得られるわけではありません。[2]

残った解からどう選ぶか

パレート最適化だけでは、A、B、Cのどれを採用するかは決まりません。これは欠点ではなく、目的間の価値判断を計算結果から分離して見せるという役割です。たとえば次のように絞ります。

  • 予算が100万円以下なら、AとBだけを比較する。
  • 誤差5%以下が必須なら、BとCだけを比較する。
  • BからCへ20万円追加して誤差を2ポイント減らす価値があるか判断する。
  • 目的値の推定誤差や条件変化に対して、結果が安定する案を優先する。

つまりパレートフロントは「自動的に正解を一つ選ぶ装置」ではなく、何を得るために何を諦めるのかを見えるようにする比較表です。

よくある誤解と注意点

「パレート最適」だから絶対に優秀、ではない

極端に安いが誤差が大きい案も、極端に正確だが高額な案も、互いに支配されなければパレート最適です。実用的かどうかは、制約や許容範囲を別に確認します。

目的と制約の定義が結果を決める

測っていない安全性や保守性は、パレート最適性の判定に入りません。重要な評価軸を落とすと、計算上は非支配でも実務上は採用できない解が残ります。

重み付き和には限界がある

複数の目的に重みを掛けて足し、一つの目的関数にする方法は簡単です。しかし、目的の単位や尺度で結果が変わり、重みの決め方そのものが価値判断になります。また、パレートフロントが非凸な場合、重みを変えても到達できない非支配解があり得ます。[3]

目的が多いほど「支配」が効きにくくなる

目的数が増えると、多くの候補が互いに一長一短となり、非支配解が大量に残りやすくなります。その場合は、許容範囲、優先順位、参照点などを追加し、意思決定に必要な範囲へ絞ります。

まとめ

パレート最適化とは、複数目的を無理に一つの点数へまとめず、他の解に全目的で負けている候補を除外し、異なるトレードオフを持つ非支配解を残す方法です。パレートフロントを得ることが探索の終点ではなく、そこから制約、優先順位、追加費用に見合う改善量を考えて一案を選ぶところまでが意思決定です。
